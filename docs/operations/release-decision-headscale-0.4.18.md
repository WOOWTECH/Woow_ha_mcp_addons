# woow_mcp_headscale 0.4.18 image decision

Status: **exact image accepted, published and anonymously verified**. Stable Release, Store synchronization and both HAOS upgrades remain separate acceptance gates.

0.4.18 publishes the output-schema metadata reviewed and merged in PR #86. All 11 Headscale tools expose the pinned child server's object output schema through public `tools/list`. The existing binding hashes and runtime drift checks remain fail closed: if a child schema or reviewed source binding changes, the gateway omits that output schema instead of inventing or forwarding unreviewed metadata.

This release does not change the 11 tool names, 29 native Headscale v0.29.4 operations, input schemas, write grants, backend requests, Origin policy, DNS fallback or state schema. Headscale alone advances from 0.4.17 to 0.4.18; the shared default remains 0.4.13 and no other Add-on version changes in this release.

Reviewed source commit: `55f35286a7b245cabb79f0a369dec6283f12adc5`. Its complete reachable history was transferred as a SHA256-verified Git bundle, checked with `git fsck`, materialized at that exact detached commit, and required to be clean before build. The one-use amd64 KubeVirt builder used Docker 28.5.2, an isolated 60 GiB Longhorn volume, no service-account token, empty namespace RBAC, default-deny networking, and public HTTP(S)-only egress.

The first supply-chain run failed closed during Syft because the VM root filesystem left only about 170 MiB for `/tmp`, while the image archive was about 223 MiB. A stage-only private diagnostic reproduced the zero-byte SBOM without exposing scanner findings. Binding `/tmp` to the isolated builder volume made the unchanged Syft command and SBOM contract pass; the complete original gate was then rerun from the start. No failed candidate was tagged or pushed, and no product source or scan policy was relaxed.

The exact tested image ID is `sha256:a9dc0c528cb3202e5b294319bac1fd8f189a606c9191e610b8ff9ca65520748e`. Container/mock acceptance passed on that ID: runtime labels, isolation, bootstrap, UID, protocol, authentication, policy, backend outage, persistence and shutdown. Source/history/all-layer secret scans, Syft and SPDX all-layer SBOMs, Grype vulnerability policy and license policy passed on the same image. The SBOM contains 193 packages and the Grype report contains 252 findings; a policy pass does not mean zero findings. See the [subject](../provenance/headscale-0.4.18-subject.json), [scan summary](../provenance/headscale-0.4.18-scan-summary.json), and [unsigned candidate provenance](../provenance/headscale-0.4.18-provenance.json).

An authenticated registry precondition returned explicit `MANIFEST_UNKNOWN` for the fixed 0.4.18 tag immediately before login. The publisher token was streamed through memory, the tested image ID alone was tagged and pushed, then Docker was logged out and its private auth directory deleted. A clean-config anonymous pull verified the manifest, config, compressed blobs and decompressed layer identities. The immutable manifest digest is `sha256:7807b65df2b8a28a2bd982ec7abea01b846b4df41e1986f101c96a12829fd6d1`; see the [published digest](../provenance/headscale-0.4.18-published-digest.json) and [published provenance](../provenance/headscale-0.4.18-published-provenance.json).

The protected PR must now pass readiness and the 0.4.17→0.4.18 upgrade comparison. Merge must create `woow_mcp_headscale-v0.4.18` and synchronize the Store before both HAOS hosts are upgraded. Post-upgrade acceptance must bind each running container to the published digest and verify 11 output schemas, all 29 native operations against disposable real Headscale backends, real pending approve/reject flows, Origin denial, state/token persistence and the non-public MCP port boundary.
