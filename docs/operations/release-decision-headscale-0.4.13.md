# woow_mcp_headscale 0.4.13 image decision

Status: **exact-source image published, anonymously verified, and accepted on an isolated HAOS VM**. Store distribution is a separate gate.

Headscale first entered the protected source branch through [PR #77](https://github.com/WOOWTECH/Woow_ha_mcp_addons/pull/77). The packaged container probe correction passed [PR #78](https://github.com/WOOWTECH/Woow_ha_mcp_addons/pull/78). The image source is merged commit `1b45bdfa5338170d2b397ef5940bb4c241f8b343`, tree `d9edb9ea38197cc7da582209dc1994855b75dd2d`. This later documentation commit is not image source.

The one-use amd64 Docker builder used a fixed Docker 28.5.2 image digest, an isolated Longhorn volume, and a Unix socket inside its own pod. The first diagnostic build found a wrong expected tool list in the container probe; it was never published. The final image was rebuilt after PR #78 from the clean full-history source above and has ID `sha256:b4a46556548818d0d6c1b49a9b38f181d21469c0126768f940fdd728f2edb3a7`. `packaging/container_acceptance.py` passed against that ID with an isolated mock backend: labels, UID/capability boundary, MCP authentication and policy, backend outage, state persistence, and shutdown.

`packaging/supply_chain.py candidate` then passed for the **same image ID**. It checked the source tree and complete Git history for secrets; scanned image layers and retained evidence for secrets; generated all-layer Syft and SPDX SBOMs; and applied the pinned Grype vulnerability and license policies. The SBOM has 193 packages and the Grype report has 238 findings; policy pass does not mean zero vulnerabilities. The candidate evidence was rechecked with `packaging/supply_chain.py verify`. See the exact [subject](../provenance/headscale-0.4.13-subject.json), [scan summary](../provenance/headscale-0.4.13-scan-summary.json), and [unsigned provenance](../provenance/headscale-0.4.13-provenance.json). Full SBOM and raw scan artifacts remain operator-local, not in this source tree.

The authenticated GHCR precondition confirmed that `0.4.13` was absent. The accepted ID alone was tagged and pushed to `ghcr.io/woowtech/amd64-mcp-headscale:0.4.13`, producing manifest `sha256:613b216622e68b188e4b7d61a93a82ba895834f82e52dae2a2b085ffc98b898d`. The builder's temporary Docker login was removed after push. Once the new package was made public, `packaging/registry_gate.py public` passed anonymous manifest, config and layer verification against the exact digest and wrote the [published digest](../provenance/headscale-0.4.13-published-digest.json) and [unsigned published provenance](../provenance/headscale-0.4.13-published-provenance.json). A separate fresh anonymous verifier streamed all 16 unique compressed remote blobs (80,644,974 bytes) and checked their sizes, hashes and uncompressed diffIDs without Docker or a local layer cache; see the [remote-layer proof](../provenance/headscale-0.4.13-remote-layers.json). The seven-product Store-registry `packaging/release_gate.py all` also passed with the same Headscale manifest digest.

The source PR checks passed, including `checks`, `readiness`, release train, and both Upgrade comparison jobs. The 0.4.13 Headscale version was not yet in the Store registry during those checks, so the existing six-image readiness result did not prove Headscale pullability; the seven-product gate above supplies that missing image check. The isolated [HAOS acceptance](ha-test-headscale-0.4.13.md) then installed and ran this exact public digest against a real Headscale backend, tested HA role enforcement, nine MCP reads, write refusal, outage recovery, restarts and partial backup/restore. Store [PR #116](https://github.com/WOOWTECH/Woow_HA_App_Store/pull/116) must be merged before the source release workflow can create its first Stable Release.

This record does not claim Store installation or production acceptance. The manually maintained image and HA entries in `RELEASE-GATES.json` remain false; this evidence file does not itself change those release gates.
