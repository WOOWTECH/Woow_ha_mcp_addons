# woow_mcp_headscale 0.4.15 image decision

Status: **exact-source image built, tested, scanned, published, and anonymously verified**. Stable Release, Store synchronization, and production HAOS upgrades are follow-up acceptance gates.

This release changes the Headscale MCP secret URL browser Origin policy. Requests with no Origin remain usable by native clients; `https://claude.ai` remains usable by the Claude.ai connector. Other, malformed, or repeated Origin headers receive HTTP 403 even when the URL contains a valid MCP token. The Bearer `/mcp` endpoint and other products keep their existing behavior. Headscale's 29 native API operations are unchanged. Only Headscale moves from 0.4.14 to 0.4.15; other active products remain at 0.4.13.

The reviewed runtime source is commit `2f47ffaa33119e6c38344df53644e7de999b427d`. The complete reachable history was transferred as a SHA256-verified Git bundle, checked out at that exact commit, verified with `git fsck`, and required to be clean before build. The one-use amd64 builder used Docker 28.5.2 image index `sha256:2a232a42256f70d78e3cc5d2b5d6b3276710a0de0596c145f627ecfae90282ac`, an isolated Longhorn volume, no service-account token, public-only HTTP(S) egress and an internal Docker Unix socket.

The exact tested image ID is `sha256:473720d776466a4ca93dc303759cc673e45e719beee4b0cb90bd3061db213c65`. Container/mock acceptance passed on that ID: runtime labels, isolation, bootstrap, UID, protocol, authentication, policy, backend outage, persistence and shutdown. The source/history/all-layer secret scans, Syft and SPDX all-layer SBOM, Grype vulnerability and license policies passed on the same image. The SBOM contains 193 packages and the Grype report contains 248 findings; policy pass does not mean zero findings. A second verification confirmed the image ID and evidence before publication. See the [subject](../provenance/headscale-0.4.15-subject.json), [scan summary](../provenance/headscale-0.4.15-scan-summary.json), and [unsigned candidate provenance](../provenance/headscale-0.4.15-provenance.json). Raw scans were not exported from the disposable builder.

The authenticated registry precondition confirmed `ghcr.io/woowtech/amd64-mcp-headscale:0.4.15` was absent. The exact scanned image ID was tagged and pushed once. Temporary Docker login credentials were removed. An anonymous pull then verified manifest, config and layer digests, yielding immutable amd64 manifest `sha256:e5abaa7a1fe520d420c857e3b1f1f36875ae7ce446e44865a9d5d55fb24956be`. See the [published digest](../provenance/headscale-0.4.15-published-digest.json) and [unsigned published provenance](../provenance/headscale-0.4.15-published-provenance.json).

Local regression verification passed 115 focused core/packaging tests and 136 Headscale child tests; `packaging/validate.py` passed. Both selected production HAOS add-ons on 0.4.14 independently exercised a disposable Headscale v0.29.4 database: missing IPv6 was repaired and preserved on repeat, and genuine Tailscale SSH challenges were approved and rejected end to end. Each host passed 18/18 gap checks, was restored to its production Headscale endpoint, and its disposable namespace and credentials were deleted. These functional results precede the 0.4.15 production upgrade; post-upgrade Origin and backend verification remain required.
