## 順便看到的（交 HM-19b 與契約）

- 管理 API 全程經 HA 的兩段 Ingress。建立帳號要用帳號清單回應的 `ETag` 當 If-Match，照常成功：這台的 Ingress 照轉 `ETag` 回應標頭
  （契約 §8.8 #111 的理由欄仍寫待實測，等 HM-19b 在正式映像上確認再改）。帳號範圍請求的 `X-MCP-Profile` 也都到了 add-on（同 HM-03a 的 UC-10）。
- 管理員在 Odoo 看得到所有標記：N×N 的對角線只對受限使用者成立（上表 T-04）。HM-19b 照這個寫期望值。

## 過程中遇到的（給 HM-19b）

- 第一次在展示機上建映像時，建置容器暫時查不到 GHCR 的名稱（Supervisor 與 SSH app 都查得到），重試就好。
- 商店重新載入一次逾時（背景工作還在跑），等工作結束再更新就好。
- 刪測試資料庫：那台 Odoo 的設定（固定資料庫、不列資料庫清單）讓 Odoo 的刪除指令認不得別的資料庫，資料庫管理也停用；改在一次性的程序裡只覆寫
  記憶體中的這個設定，呼叫 Odoo 自己的刪除函式（含檔案儲存）。設定檔沒改。
- P9 工具用 HM-16 的 `ha_p9_admin.mjs`，配 `claude-delivery` 的面板 API（HM-27 的面板改動在後者）。
