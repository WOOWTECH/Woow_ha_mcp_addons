# Headscale HA Core 2026.11 Compatibility Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Release Headscale MCP 0.4.14 so its HA management GUI works with reviewed Core 2026.11.0 and 2026.11.1, while the other products retain their published 0.4.13 versions.

**Architecture:** Keep the shared role verifier's closed version list. Add only the two Core releases after checking all 25 consumed/adjacent source files and the Supervisor proxy. Introduce a bounded per-product version override for Headscale across the manifest, runtime, build, candidate scan and registry gate; the default remains 0.4.13.

**Tech Stack:** Python 3.13, GitHub Actions, Docker/OCI, Home Assistant Supervisor, KubeVirt test VM.

**Files:** `docs/ha-role-core-contract.md`, `packages/mcp-admin-core/mcp_admin_core/ha_role.py`, `tests/test_ha_role.py`.

1. Record the immutable upstream tags and blob comparison for Core 2026.10.4 → 2026.11.0 → 2026.11.1 and Supervisor 2026.10.4 → 2026.10.5. Review every changed hunk; document why the fields, `require_admin`, `config/auth/list`, result envelope, and Supervisor frames still match.

### Task 2: Isolate the Headscale release version

**Files:** `packaging/inputs.json`, `packaging/validate.py`, `packaging/container_acceptance.py`, `packaging/supply_chain.py`, `packaging/registry_gate.py`, `packaging/check_release.py`, `.github/workflows/ci.yaml`, `.github/workflows/release.yaml`, `packages/mcp-admin-core/mcp_admin_core/__init__.py`, `packages/mcp-admin-core/mcp_admin_core/gateway.py`, `packages/mcp-admin-core/mcp_admin_core/run_product.py`, `tests/test_unconfigured_connect.py`, `packaging/test_validate.py`.

1. Add `version_overrides: {headscale: 0.4.14}` to the fixed build inputs. `validate.version_for(app)` returns the override or default and rejects unknown products; the runtime carries the same fixed map and validation checks equality.
2. Make the Headscale manifest, candidate tag, image labels, GHCR lookup and publish tag use `version_for`. The other seven products remain 0.4.13.
3. Pass the Headscale version through `ManagementOptions.product_version` and use it for both `capabilities.product.version` and MCP `serverInfo.version`; keep the other products' reported version unchanged.
4. Update workflow build tags/args and strict validator together. Keep one build, scanning before registry login, and exact-image publication.
5. Run `python packaging/validate.py`, the focused packaging tests, and the unit suite. Assert a tampered override, tag or build arg fails validation.
